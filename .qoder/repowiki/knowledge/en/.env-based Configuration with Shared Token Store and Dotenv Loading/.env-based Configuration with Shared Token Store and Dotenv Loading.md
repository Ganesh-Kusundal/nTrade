The nTrade framework uses a lightweight, environment-variable-driven configuration system centered on `.env` files loaded via `python-dotenv`, combined with a shared JSON token store for broker credentials. There is no centralized config object or schema validator; instead, configuration is consumed directly from `os.environ` at the point of use.

**How configuration is loaded**
- The single entry point for loading `.env` is `ntrade/brokers/dhan_auth.load_env(env_path=".env")`, which calls `dotenv.load_dotenv(Path(env_path).absolute())`. This function is invoked inside `get_tradehull()` before any environment variables are read.
- All Dhan-specific configuration keys are read from `os.environ` (or an injected `env` dict) inside `dhan_auth.get_tradehull`: `DHAN_CLIENT_ID`, `DHAN_ACCESS_TOKEN`, `DHAN_PIN`, `DHAN_TOTP_SECRET`, `DHAN_TOKEN_PATH`, `DHAN_COOLDOWN_PATH`, plus `DHAN_EXPIRY_BUFFER_S` (a module-level constant controlling proactive token refresh).
- The `env_path` parameter defaults to `".env"` and is threaded through `TradingSession.connect()`, `Market.__init__`, `DhanBroker.__init__`, and `DhanAuthProvider.__init__`, so callers can override the dotenv file location per session.

**Shared token store (JSON file)**
- Successful authentication persists the working token to a JSON file at `DHAN_TOKEN_PATH` with fields `access_token`, `expires_at`, `expires_at_ms`, and `source` (STORE/ENV/TOTP). The file is created with mode `0o600` for security.
- A separate cooldown file at `DHAN_COOLDOWN_PATH` tracks TOTP attempt timing (`last_attempt_at`) to enforce a 90-second cooldown between PIN+TOTP attempts.
- The auth flow follows a strict priority: (1) load from shared store if present and not near expiry, (2) fall back to `DHAN_ACCESS_TOKEN` as bootstrap seed only, (3) mint via PIN+TOTP if available. Invalid tokens in the store are cleared automatically when a data-plane probe detects DH-906 errors.

**Propagation through the stack**
- `check_connection.py` and scripts call `get_tradehull(env_path=...)` directly.
- `facade.Market` and `kernel.trading_session.TradingSession.connect()` accept `env_path` and `env` kwargs and pass them to `BrokerRegistry.get()`, which constructs the broker with those parameters.
- `DhanBroker.__init__` stores `env_path` and `env` and forwards them to `DhanAuthProvider`, which then passes them to `dhan_auth.get_tradehull`.
- Tests inject `env` dicts directly to avoid filesystem side effects, bypassing `.env` files entirely.

**Constraints and conventions**
- `DHAN_CLIENT_ID` is mandatory; missing it raises `ValueError("DHAN_CLIENT_ID is not set")`.
- If both `DHAN_PIN` and `DHAN_TOTP_SECRET` are missing after store/env fallbacks, `ConnectionError` is raised instructing users to regenerate their access token.
- `Dhan_Tradehull` must be installed; otherwise `ImportError` is raised with installation instructions.
- JWT expiry is parsed client-side using base64 decoding of the payload; tokens within `EXPIRY_BUFFER_S` (default 900s) are treated as expired and refreshed proactively.
- No pydantic models, YAML/TOML schemas, or typed settings classes are used — configuration is raw string values read from `os.environ`.

**What this means in practice**
Configuration is intentionally minimal and implicit: there is no global config registry, no validation layer, and no default configuration file shipped with the package. Users supply secrets via `.env` files (one per environment) and optionally override paths per-session. The shared token store decouples credential persistence from the dotenv mechanism, enabling multi-process sharing of valid tokens across runs.

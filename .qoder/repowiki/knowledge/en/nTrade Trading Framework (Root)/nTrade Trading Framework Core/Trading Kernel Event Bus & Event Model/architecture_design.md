Two cooperating sub-packages form the kernel's coordination layer:
- `ntrade/events/` declares the canonical event schema: a frozen `dataclass` base `Event` (with deterministic `ts` from `TradingClock` and auto-generated `event_id`) plus domain-specific subclasses in `market.py`, `order.py`, `portfolio.py`, `risk.py`, and `lifecycle.py`. All events are exported through `events/__init__.py` as the single public surface.
- `ntrade/kernel/` hosts the runtime: `event_bus.py` implements `EventBus`, a reentrant-locked pub/sub dispatcher that walks the MRO so subscribers of a base class receive subclass events, swallows handler exceptions, and keeps a bounded deque history for replay. `clock.py` defines the `TradingClock` interface with `LiveClock`, `ReplayClock`, and `SimulationClock` implementations to guarantee zero parity across live/replay/backtest. `context.py` provides `TradingContext`, a thread-safe container holding bus, clock, instruments, portfolio, and account. `session.py` (`TradingKernel`) wires the full engine stack (Market, Candle, Indicator, Strategy, Risk, Portfolio, Order engines) around a shared `EventBus` and `TradingContext`, exposing start/stop, replay, and broker execution helpers. `resilient.py`, `runner.py`, and `trading_session.py` wrap the kernel for fault tolerance and orchestration.

Dependency direction is strictly one-way: kernel components depend on `events.*`; engines consume events via the bus; no engine publishes directly to another subsystem — all cross-cutting communication flows through `EventBus.publish`.

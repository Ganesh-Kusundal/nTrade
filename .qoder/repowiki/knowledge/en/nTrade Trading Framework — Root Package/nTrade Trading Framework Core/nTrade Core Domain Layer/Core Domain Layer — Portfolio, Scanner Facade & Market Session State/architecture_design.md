Three cohesive sub-packages under `ntrade.domain` with inward-only dependencies:
- `portfolio.py` declares immutable dataclasses `Position` and `Holding`, plus composite classes `Portfolio` and `Account` that own lists of those entities and optionally hold a `BrokerAdapter` reference. Both composites expose `from_broker` classmethods and instance `refresh()` methods to rebuild themselves from live broker data, and implement collection protocols (`__len__`, `__iter__`, `__getitem__`) so they behave like sequences.
- `scanner.py` defines an abstract `Scanner` base (with `scan(session, **kw)` returning raw unranked results) and a `ScannerFacade` that registers built-in scanners from `ntrade.scanners.builtin` at construction time via `_register_builtins`. The facade exposes named entry points (`gap`, `volume`, `momentum`, `breakout`, `imbalance`, `custom`) and centralizes per-scanner rate-limiting + parameter-keyed caching through `_run`, which sorts results by score and assigns rank.
- `session.py` provides the `MarketState` enum and `SessionState` dataclass implementing a simple state machine with `enter(state, now=...)` transitions and an `is_open` property.

Dependency direction is strictly inward: domain objects depend only on `dataclasses`, `typing`, `datetime`, and `enum`; broker and instrument types are imported lazily inside `TYPE_CHECKING` blocks to avoid circular imports between domain, kernel, and brokers layers. The facade's built-in scanners are loaded lazily from `ntrade.scanners.builtin`, keeping this module decoupled from concrete scanner implementations.

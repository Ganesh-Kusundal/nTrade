The module exposes two interchangeable `ExecutionTarget` implementations sharing the same `submit(intent) -> OrderRejectedEvent | None` contract: `BrokerExecution` (live, delegates to a `BrokerAdapter` via an instrument's `order.place`, tracks open orders in `_open`, polls for lifecycle events, and publishes `OrderAcceptedEvent`/`OrderFilledEvent`/`OrderUpdatedEvent`/`OrderTimeoutEvent`/`OrderRejectedEvent` through `ctx.bus`) and `SimulatedExecution` (deterministic, derives fill price from instrument quote state with configurable slippage). Both are registered by name (`broker`, `simulated`) and dispatched through `ExecutionRouter`, which resolves the target by `intent.strategy` falling back to a configured `default`. Cost calculation is centralized in `costs.py` via pluggable `SlippageModel` and `CommissionModel` ABCs plus `IndianStatutoryCosts` (STT, exchange charges, SEBI fee, GST, stamp duty) selected per instrument class; both executors compute commission then statutory costs identically so paper/live PnL converges. `retry.py` supplies stdlib-only `RetryPolicy` (exponential backoff + jitter) and `RateLimiter` (thread-safe token bucket) for broker API resilience. The module's `__init__.py` re-exports all public types as the single execution surface.

The module is organized around two interchangeable `ExecutionTarget` implementations sharing the identical `submit(intent) -> OrderRejectedEvent | None` contract: `BrokerExecution` (live, delegates to an instrument's `order.place`, tracks open orders in `_open`, polls via `poll()` for lifecycle events, and publishes `OrderAcceptedEvent`/`OrderFilledEvent`/`OrderUpdatedEvent`/`OrderTimeoutEvent`/`OrderRejectedEvent` through `ctx.bus`) and `SimulatedExecution` (deterministic fill derived from instrument quote state with configurable slippage). Both expose a class-level `name` attribute (`"broker"`, `"simulated"`) and are registered by name into `ExecutionRouter`, which resolves the target by `intent.strategy` falling back to a configured `default`. Cost calculation is centralized in `costs.py` via pluggable `SlippageModel` and `CommissionModel` ABCs plus `IndianStatutoryCosts` (STT, exchange charges, SEBI fee, GST, stamp duty) selected per instrument class; both executors compute commission then statutory costs identically so paper/live PnL converges. `retry.py` supplies a frozen `RetryPolicy` (exponential backoff + jitter) and thread-safe `RateLimiter` (token bucket), while `rate_limit.py` provides `BrokerRateGate` with multi-window sliding windows per Dhan quota class. The module's `__init__.py` re-exports all public types as the single execution surface.

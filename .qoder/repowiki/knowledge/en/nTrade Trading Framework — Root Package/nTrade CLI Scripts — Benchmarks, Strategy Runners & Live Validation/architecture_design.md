Each script is a self-contained entry point with no inter-script dependencies; dependency direction is strictly outward into the installed `ntrade` package (`ntrade.kernel`, `ntrade.engines`, `ntrade.sources`, `ntrade.runner`). Scripts fall into three roles: (1) benchmarks — `benchmark_latency.py` measures tick throughput via `measure_tick_throughput` and writes `.benchmarks/latency.json`; (2) end-to-end strategy runners — `ema_cross_run.py`, `paper_gate_run.py`, `live_runner_run.py` construct a `TradingKernel(mode='replay'|'live', clock=ReplayClock|LiveClock, timeframe=...)`, register an `Index` instrument and `EmaCrossStrategy`, inject a feed source (`SimulatedFeedSource`, `SyntheticMarketFeedSource`, or `build_source`), run the event pipeline, then stop and report; (3) live health checks — `live_read_check.py` and `live_smoke.py` connect via `TradingSession.connect('dhan')` and exercise read-only endpoints. The `pre_deploy_check.py` orchestrates the other scripts as subprocess stages, enforcing a token-freshness check before running paper-gate → live-read → live-smoke in order. The `live_runner_run.py` additionally wires a `LiveRunner` harness around the kernel and source to drive either synthetic offline ticks or a real Dhan websocket.

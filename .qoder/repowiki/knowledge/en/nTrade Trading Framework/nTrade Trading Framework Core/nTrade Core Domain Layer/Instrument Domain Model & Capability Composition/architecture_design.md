The module centers on a single abstract root `Instrument` (base.py) that owns all mutable state (`_quote`, `_depth`, `_history`, `_stream`, `_indicators`, `_signals`, `_session`, `_market_status`) and delegates behavior to six lazy `@cached_property` capability objects defined in capabilities.py. Concrete asset classes live in separate files: cash instruments (Equity, Index, ETF, Currency, Commodity, Bond, Crypto, Spot) in cash.py; derivative instruments (Future, Option, SyntheticInstrument) in derivatives.py; and composite/auxiliary types (OptionChain in chain.py, Expiry and OptionPair in expiry.py). The `__init__.py` re-exports the public surface. Capability classes are intentionally stateless views that hold only a reference back to their owning Instrument; they never mutate state directly — mutations go through the Instrument's own methods (e.g. `apply_quote`, `refresh`, `hydrate`). Broker transport is hidden behind a `BrokerAdapter` accessed via `instrument.broker_adapter` / `instrument.broker`, with provider-specific extensions resolved through `ExtensionCapability.__call__` which delegates to `BrokerExtensionFacade`. Dependency direction is strictly inward: concrete instrument subclasses depend on base.Instrument; capabilities depend on Instrument; option-chain helpers depend on Option; no cross-imports between sibling asset-type modules.

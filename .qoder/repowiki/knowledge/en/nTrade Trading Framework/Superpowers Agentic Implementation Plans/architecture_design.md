Each file is a self-contained plan for one release batch (G2–G4), organized into numbered Task Groups (A–E) with individual tasks that follow a strict five-step pattern: write failing test → run to verify failure → minimal implementation → run tests → full suite green. Plans reference concrete source files under `ntrade/` and `tests/`, declare interfaces as dataclass contracts, and enforce global constraints (Python 3.10+, pytest runner at `.venv/bin/python -m pytest -q`, events as frozen dataclasses extending `ntrade.events.base.Event`, broker-agnostic domain layer). Dependency direction is outward only: plans describe changes to existing modules without restructuring them, and each task's gate is a passing test suite rather than a commit. The four plans form a chronological progression from G2 (live harness + synthetic tick engine + risk circuit breakers) through G3 (zero-parity, thread-safety, money-path fixes) to G4 (parity & complexity batch) and the Integration Completeness Batch (wiring 10 planned-but-unintegrated subsystems into the hot path).

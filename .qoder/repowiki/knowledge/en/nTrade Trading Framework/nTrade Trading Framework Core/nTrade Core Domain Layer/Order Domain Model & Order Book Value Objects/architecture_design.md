Two cooperating files form a thin domain layer around order execution:
- `order.py` declares the mutable `Order` dataclass plus three str-based Enums (`OrderSide`, `OrderType`, `TradeType`, `OrderStatus`) and an `OrderFacade` that provides fluent entry methods (`buy`, `sell`, `limit`, `market`, `stop`, `cover`, `bracket`). The facade delegates all I/O to `instrument.broker_adapter.place_order`, keeping the domain free of broker specifics. `Order` methods like `cancel`, `modify`, `refresh`, `executed_price` follow the same pattern: delegate to the instrument's broker adapter when present.
- `book.py` defines frozen dataclasses (`OrderBookEntry`, `OrderBook`, `TradeBookEntry`, `TradeBook`) that wrap raw broker dicts/DataFrames into immutable, thread-safe value objects with `for_symbol` filtering and `to_dict` escape hatches for backward compatibility.
- `__init__.py` re-exports only the public API surface (`Order`, `OrderFacade`, and the four enums), hiding internal implementation.
- Dependency direction is inward-only: this module depends on `ntrade.domain.instruments.base.Instrument` via `TYPE_CHECKING` to avoid circular imports; nothing in the rest of the system depends back on broker internals.

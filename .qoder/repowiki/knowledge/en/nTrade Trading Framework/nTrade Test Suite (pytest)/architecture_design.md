Tests are organized as one pytest module per production subsystem, mirroring the ntrade package structure: kernel/session tests (`test_engine_pipeline.py`, `test_kernel_engines.py`), Dhan broker adapter tests (`test_dhan_broker.py`, `test_dhan_auth_unit.py`, `test_dhan_feed*.py`), engine tests (`test_candle_engine.py`, `test_indicators.py`), domain/accounting tests (`test_portfolio_account.py`, `test_costs_india.py`, `test_futures_carry_costs.py`), and integration/end-to-end tests (`test_integration_pipeline.py`, `test_replay_backtest.py`). Each test file constructs a `TradingKernel` in replay or live mode, registers instruments via `Equity/Index/Option`, and drives behavior by publishing events on `kernel.bus` or by attaching synthetic sources like `SyntheticMarketFeedSource`. Broker tests avoid real network calls by constructing objects with `cls.__new__(cls)` and injecting stubs via `types.SimpleNamespace`. Integration tests wire `PaperBroker` + `SyntheticMarketFeedSource` to exercise the full feed → kernel → strategy → risk → execution → portfolio chain. A dedicated `test_benchmark.py` uses `measure_tick_throughput` for latency measurement.

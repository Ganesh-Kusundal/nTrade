Two cooperating sub-packages under ntrade:
- `runner/` provides the execution layer. `live_runner.LiveRunner` is the main orchestration class: it attaches a `MarketFeedSource`, starts the `TradingKernel`, runs a timed `step()` loop that polls orders (`poll_orders`) and syncs positions (`sync_positions`), publishes heartbeats, watches for feed stalls via a tick-count watchdog, and reacts to `RiskHaltedEvent` by activating broker kill switches. `feeds.build_source` is a factory that returns either `SyntheticMarketFeedSource` or `DhanMarketFeedSource` based on a string flag. `gate.build_paper_report` walks the kernel's event bus history to reconstruct equity and produce a checklist for paper→live validation. `bench.measure_tick_throughput` micro-benchmarks the event pipeline. The package `__init__.py` re-exports only these four public symbols.
- `scanners/builtin.py` implements concrete `Scanner` subclasses (`GapScanner`, `VolumeSpikeScanner`, `MomentumScanner`, `BreakoutScanner`, `ImbalanceScanner`) that iterate over `session.kernel.ctx.instruments_snapshot()` and emit `ScannerResult` objects with signal, score, matched_conditions, and indicator_values. Each scanner falls back gracefully when quote/indicator data is missing.
Dependency direction is one-way: runner depends on `ntrade.events.*` and `ntrade.sources.*`; scanners depend on `ntrade.domain.scanner.Scanner` and `ntrade.domain.scanner.ScannerResult`. Neither package imports each other.

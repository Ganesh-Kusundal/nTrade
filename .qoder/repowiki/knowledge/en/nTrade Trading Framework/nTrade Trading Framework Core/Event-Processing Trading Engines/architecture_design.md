Each engine is a self-contained class that subscribes to specific event types on `context.bus` during `__init__`, processes events through dedicated handler methods (e.g. `on_tick`, `on_candle_closed`, `on_signal_approved`), and publishes downstream events — forming a unidirectional pipeline: MarketEngine normalizes ticks/quotes/depth into QuoteUpdatedEvent → CandleEngine aggregates into CandleClosedEvent → IndicatorEngine computes bundles via pandas `compute_bundle` and emits IndicatorUpdatedEvent → StrategyEngine fans events to registered Strategy subclasses → RiskEngine screens signals emitting SignalApprovedEvent or SignalRejectedEvent → OrderEngine materialises approved signals into OrderIntentEvent → PortfolioEngine updates Position/Balance read models from fills. PositionSyncEngine runs independently to reconcile broker-reported positions/balance back into the kernel. All cross-engine communication is strictly event-driven; engines access shared read models (`ctx.instrument`, `ctx.portfolio`, `ctx.account`) but never mutate each other directly. The `Strategy` base class defines hook methods that `StrategyEngine` dispatches to all registered strategies, swallowing per-strategy exceptions so one failing strategy cannot crash the pipeline. Dependency direction is inward only: engines depend on `ntrade.events.*` and `ntrade.domain.*` but are not imported by domain/event modules.
